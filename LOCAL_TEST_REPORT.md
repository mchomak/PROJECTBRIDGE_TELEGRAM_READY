# ProjectBridge — отчёт локального E2E-аудита MVP

Дата проверки: 15 ноября 2026  
Среда: локальная Windows-машина, Docker Compose  
Границы: только тестирование и анализ. Исходники приложения, API, модели, миграции и .env в ходе аудита не исправлялись и не изменялись. Тестовые аккаунты, проект и связанные данные оставлены в локальной базе.

## 1. Executive Summary

Проверка охватила 37 функциональных сценариев: **23 PASS, 3 FAIL, 5 BLOCKED и 6 NOT IMPLEMENTED**. Полные автоматические наборы прошли: backend — 441 тест, frontend — 109 тестов (14 файлов), всего **550 тестов**. Три отдельные проверки качества кода завершились с ошибками: frontend format check, Ruff format check и Ruff lint. Они не были исправлены.

Основные локальные сценарии — регистрация и верификация, роли проекта, приглашение, анкета, Project State, чат, документы, их архивирование/восстановление и жизненный цикл проекта — прошли доступные пользовательские проверки. Выявлены три воспроизводимые ошибки: интерфейс не предлагает восстановление версии анкеты после ответа 409; анализ противоречия через DeepSeek вернул некорректный результат; генератор спецификации сохранил оборванный текст как готовую версию.

Индексация документов и RAG заблокированы отсутствием OpenAI credentials для настроенного embedding-провайдера. Отдельные сценарии анализа сообщений, разговора и документов, а также встроенный reranking отсутствуют в фактическом приложении. Поэтому MVP **не готов к полноценной ручной приёмке всего заявленного в этом аудите набора, особенно AI/RAG**, хотя основные совместные рабочие процессы можно вручную тестировать.

### Реальные запросы и содержательная оценка

За весь аудит сделано ровно **2 внешних запроса DeepSeek**, без повторов успешных вызовов и без массовых циклов. OpenAI-запросов — 0.

1. Анализ проекта/противоречия: provider DeepSeek, model deepseek-flash, профиль v2. Запрос дошёл до провайдера; сохранённая статистика — 3 504 входных и 4 096 выходных токенов, одна попытка. Результат завершился provider_response_invalid, пригодного структурированного анализа и предложения не получено. Изменений Project State после вызова нет.
2. Генерация спецификации: provider DeepSeek, model deepseek-flash, профиль v2. API сохранил версию 4 со статусом ready; текст содержит сведения о каталоге, бюджете, этапах, задаче и нерешённом противоречии, но заканчивается на незавершённом фрагменте «позднее сообщение про». Получено 1 209 входных и 8 192 выходных токена; использован весь доступный лимит вывода.

Всего: 4 713 входных и 12 288 выходных токенов. Внутренняя оценка стоимости по профилям — $0.01965060: $0.00819420 за анализ и $0.01145640 за спецификацию. Это оценка приложения, не счёт провайдера; фактическое списание DeepSeek проверить нельзя. До HTTP-вызова для отсутствующих OpenAI credentials запросы не доходили, токены не расходовались.

При live-проверке смены модели между разными генеративными функциями результат не подтверждён: все проверенные генеративные профили указывают на одну модель deepseek-flash, а OpenAI embedding-маршрут не смог пройти credential preflight. Наличие разделённых профилей подтверждено, успешная работа с отличающимися моделями — нет.

### Ограничение спецификации

Технический контракт генерации спецификации в этой версии включает данные паспорта и общего Project State. Документы, переписка и RAG явно не входят в перечисленные источники генерации. Поэтому их отсутствие в спецификации не классифицировано как дефект реализации.

## 8. Bugs and Issues

### PB-E2E-01 — Medium — восстановление черновика анкеты после 409

- **Шаги:** открыть черновик заказчика; после создания черновика изменить паспорт исполнителем; отправить ответы заказчиком.
- **Ожидалось:** после конфликта версии UI предлагает обновить версию черновика и продолжить.
- **Фактически:** сервер возвращает 409 и локализованное сообщение; экран показывает ошибку без кнопки обновления. После прямого вызова документированного API refresh отправка проходит.
- **Доказательства:** screenshot questionnaire-submit-debug.png; backend 409; браузерный сценарий.
- **Предполагаемая причина:** UI распознаёт stale-version ошибку по английскому фрагменту “passport changed after this draft started”, тогда как фактическое сообщение локализовано. Это вывод из наблюдаемого поведения; исходники не изменялись.

### PB-E2E-02 — High — DeepSeek не вернул валидный анализ противоречия

- **Шаги:** загрузить документ с гостевым оформлением; добавить в чат требование кабинета; запустить contradiction_detection.
- **Ожидалось:** структурированный анализ с обоими источниками и предложением исполнителю, без самостоятельной записи в Project State.
- **Фактически:** запрос достиг DeepSeek, но приложение отклонило ответ как provider_response_invalid; предложения нет. Project State не изменился.
- **Технические данные:** deepseek-flash, профиль v2, 3 504 входных / 4 096 выходных токенов, 1 попытка, оценочная стоимость $0.00819420.
- **Предполагаемая причина:** несоответствие ответа провайдера ожидаемому структурированному контракту возможно, но по доступным сохранённым данным подтвердить конкретную причину нельзя.

### PB-E2E-03 — Medium — обрезанная спецификация сохранена как готовая

- **Шаги:** создать и сгенерировать спецификацию из тестового проекта.
- **Ожидалось:** завершённый текст либо ошибка/явное состояние неполного результата при достижении лимита.
- **Фактически:** последняя фраза обрывается на «позднее сообщение про», но API сохраняет версию 4 со статусом ready.
- **Технические данные:** deepseek-flash, профиль v2, 1 209 входных / 8 192 выходных токена; вывод достиг лимита; оценочная стоимость $0.01145640.
- **Предполагаемая причина:** результат, достигший максимального лимита вывода, принят без распознанной проверки завершённости. Это наблюдение по ответу API и тексту; код не менялся.

### PB-E2E-04 — Medium — документная индексация заблокирована конфигурацией

- **Шаги:** загрузить поддерживаемые документы и дождаться фоновой обработки.
- **Ожидалось:** обработка до готового embedding/index, если провайдер сконфигурирован.
- **Фактически:** извлечение текста и chunks завершились, но все пять документов имеют failed processing status; OpenAI credential отсутствует в runtime, внешний запрос не отправлялся. Поэтому RAG не готов к проверке.
- **Технические данные:** профиль document_embedding настроен на OpenAI text-embedding-3-small; доступный runtime не содержит соответствующего credential.
- **Предполагаемая причина:** локальная конфигурация не предоставляет настроенный провайдеру credential. Это блокер среды; отсутствие ключа не маскировалось и маршрутизация не менялась.

### PB-E2E-05 — Low — список жизненного цикла требует ручного обновления

- **Шаги:** исполнитель создаёт запрос архивации; заказчик оставляет экран документов открытым и ожидает появление запроса.
- **Ожидалось:** новое состояние отображается без ручной перезагрузки либо интерфейс явно обновляет список.

- **Предполагаемая причина:** состояние запроса не обновляется в открытом клиенте автоматически. Причина не проверялась глубже.

## 9. Recommendations

### До полноценной ручной проверки

1. Обеспечить локальную конфигурацию embedding-провайдера согласно разрешённому проектом способу, если в объём ручной проверки входят RAG и индексация. Не отправлять реальные запросы к неподготовленному провайдеру.
2. При ручной проверке анкеты учитывать обходной путь через штатный API refresh; UI-сценарий после stale-version 409 сейчас не восстанавливается самостоятельно.
3. Проверять предложения и спецификации DeepSeek только как экспериментальные черновики: анализ противоречия не сформировал предложение, генерация спецификации вернула незавершённый текст.

### До демонстрации функций AI

1. Добиться валидного структурированного ответа в анализе противоречий и проверить источники с обеих сторон.
2. Проверять полноту генерации спецификации до публикации/передачи как результата; статус ready сейчас не гарантирует завершённый текст.
3. Повторить live-проверку разных моделей/провайдеров после подготовки локального credential для embedding-маршрута и зафиксировать фактические профили и usage.

### Можно отложить

1. Обновление списка lifecycle-запросов без перезагрузки страницы.
2. Удаление записей Project State, если оно входит в будущий продуктовый scope; endpoint удаления в проверенном сценарии отсутствует.
3. Если продукт требует явных зависимостей, учесть, что в проверенной модели Project State их нет; связь задач с этапом зависимостью не является.
4. Форматирование и Ruff для указанных файлов следует обработать отдельно от этого тестового аудита; пользовательские изменения оставлены нетронутыми.

При этом аудит **не подтверждает готовность MVP к полной ручной приёмке**: анализ противоречий через DeepSeek завершился ошибкой; генератор спецификации сохранил оборванный текст как ready; индексация и RAG заблокированы конфигурацией embeddings; часть заявленных AI-сценариев фактически не реализована. Дополнительно есть дефект восстановления анкеты после изменения версии паспорта.
