## What must work

Both participants upload, list, and download shared documents backed by persistent Django storage. The backend validates exact size, supported format/content, generated storage keys, membership, and cleanup of partial writes.

## From the brief, verbatim

> Both participants can list, upload, and download all project documents.

## Spec sections

Spec sections 3, 4.5, 5, 6, and 7. Update document model/API/security/storage documentation and record the malware-scanning production gate.

## Acceptance criteria

- [ ] Document metadata and lifecycle rows are stored in PostgreSQL while bytes use Django default storage on the persistent local media volume.
- [ ] Server rejects files over 20*1024*1024 bytes and rejects unsupported/mismatched content among PDF, DOCX, TXT, and Markdown; MIME from the browser is not trusted. Zero-byte TXT/Markdown files are accepted and remain queued until Stage 09 processing.
- [ ] Generated UUID storage keys are independent of the display name, SHA-256 is computed, and failed metadata writes clean up saved bytes.
- [ ] Both active members can list and download through the authenticated backend; no public file URL or private-document visibility exists.
- [ ] UI supports upload progress, validation feedback, details/queued status and retry; tests cover size/type, traversal, cross-project access, and partial cleanup.
