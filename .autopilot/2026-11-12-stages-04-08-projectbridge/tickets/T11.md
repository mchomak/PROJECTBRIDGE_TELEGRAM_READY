# T11 - Validate browser origins for authenticated WebSockets

**Requirements:** R65  
**Blocked by:** T08  
**Zone:** `backend/apps/chat/routing.py`; `backend/config/asgi.py`; `backend/apps/chat/tests/test_chat_api.py`; `backend/apps/health/tests/test_asgi.py`; security/API decision docs  
**Status:** done

## Finding

The authenticated WebSocket stack checked session and project membership,
but did not validate the browser `Origin`. A foreign page could attempt to
use an active participant's browser session to subscribe to project events.

## Acceptance criteria

- [x] Only an origin configured by `FRONTEND_BASE_URL` or
  `CSRF_TRUSTED_ORIGINS` reaches the existing session and membership checks.
- [x] Missing and foreign origins are rejected.
- [x] A configured frontend origin still reaches chat; anonymous and
  non-member connections remain rejected with a valid origin.
- [x] HTTP routes and session/member authorization behavior are unchanged.
- [x] `/ws/v1/health/` continues to accept originless health probes.
- [x] Security documentation and ADR-005 describe the configured-origin
  boundary.
