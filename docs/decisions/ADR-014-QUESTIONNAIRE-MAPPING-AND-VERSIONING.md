# ADR-014: Questionnaire Versioning and Passport Mapping

**Status:** Accepted
**Date:** 2026-11-12
**Decision owners:** Project owner

## Context

Questionnaires must have deterministic questions and preserve submitted answers while updating the project passport. The schema, mapping, and correction rules were not previously fixed.

## Decision

- Questionnaire definitions are product-authored, versioned JSON schemas. A released version is immutable; new submissions use the latest version for their project type, while corrections retain the original submission's schema version.
- Answers are stored separately from passport fields with their source and confirmation state. Submission applies only the documented answer-to-passport mapping; implicit mapping by question labels is not used.
- Empty optional answers do not clear passport values. A differing answer and existing nonempty passport value are retained as a conflict, leaving the passport unchanged until executor review. Applying an answer uses the versioned project passport service; keeping the passport value leaves it unchanged.
- A correction creates a superseding draft and preserves the original submission and answers. The customer edits only the new draft.
- Conflict review is executor-only. Questionnaire questions and branches are deterministic and are not generated by AI.

## Consequences

- Changes to questions, branching, validation, or mappings require a new schema version; existing submissions continue to be interpreted using their recorded version.
- Passport updates remain explicit and version-checked. Conflicting values require a recorded human decision instead of silent overwrite.
- Corrections and conflicts add durable records and review steps, preserving provenance and history at the cost of additional storage and executor work.
